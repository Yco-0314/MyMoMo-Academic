# GIS Mode — Design Spec

**Status:** Draft (brainstorming output, pre-plan)
**Date:** 2026-06-16
**Author:** Cong Yu + Claude
**Repo:** MyMoMo-GIS-Academic (a fork of the published abm-auto; GIS developed here so the public repo stays stable)

---

## 1. Vision & scope

Add a **GIS modeling mode** to the autonomous ABM pipeline: a user describes a
geographic model in one sentence and gets a working GIS-ABM simulation — the same
"plain language → runnable model" promise, now on real geographic space.

- **Additive, parallel mode.** GIS spaces sit *alongside* the existing abstract
  Grid/Network, not as a replacement.
- **Coverage (destination):** raster → point → vector spatial types; autonomous
  (codegen + intent), with cross-domain / method-transfer on GIS as later widening.

### Hard constraints (load-bearing)

1. **Zero changes to the existing abstract path.** Grid / Network / existing
   codegen / existing intent values are untouched. Consequence: the published
   engine's `engine_oracle.py` science + byte-diff gates stay green *for free*
   (we don't modify that path), and a future merge back into the main repo is a
   clean add, not a refactor.
2. **GIS activates only on signal.** The pipeline routes to the GIS path **only**
   when intent detection (a) sees an explicit GIS/geographic mention, or (b)
   infers the story is suitable for GIS. **Default is the existing non-GIS path.**
3. **GIS-intent-but-no-data is a first-class halt.** If GIS is detected but no
   geographic data source is provided, the pipeline stops and asks (reusing the
   ⑤ clarification-halt), rather than failing.

### Design principle: hard but right

Prefer the correct choice over the easy one whenever it affects the framework's
long-term credibility: **real** open geographic data over synthetic toys;
**CRS-agnostic / reprojection-first** over a hardcoded CRS; **rigorous** spatial
gates over hand-wavy ones. The framework targets **global** cities; region-specific
geographic data (including China) is introduced later as widening — so nothing in
the architecture may assume a single region or CRS.

## 2. The 6 capability layers (the substrate)

All **ADD**, none **refactor**:

| Layer | What | Skeleton scope |
|---|---|---|
| **L1 Space** | `RasterSpace` / `PointSpace` / `VectorSpace`, parallel to Grid/Network | RasterSpace only |
| **L2 Geo data I/O** | readers (GeoTIFF / shapefile / GeoJSON / CSV-coords), CRS, extent, nodata | GeoTIFF reader only |
| **L3 Spatial ops** | neighbors / distance / point-in-polygon / adjacency / density | raster neighborhood + metric distance |
| **L4 Codegen + intent** | recognize GIS story; emit "load geo data + run on GIS space" | minimal: one-sentence → raster-SIR |
| **L5 Map output** | render results on a map | matplotlib `imshow` + agent scatter |
| **L6 Verification** | GIS science gates / reference models | one spatial-spread gate |

## 3. Dependency policy (Risk 1 — GDAL is install-hell)

GIS libraries (`rasterio`, `geopandas`, `shapely`, `fiona`) pull in **GDAL**, a
notorious install/version trap. The base package must stay light.

- GIS deps go in an **optional extra**: `pip install abm-auto[gis]`.
- The GIS path **lazy-imports** them; the non-GIS path never touches them.
- CI: a **separate job** installs `[gis]` and runs the GIS tests; the base CI job
  stays light and GDAL-free.

---

## 4. Decomposition: walking skeleton (A → B), then widen

The skeleton is split so the **deterministic** part ships and gates first, and the
**LLM-dependent** part (the riskiest) builds on a proven base — the same discipline
as `engine_oracle` (handcrafted reference model first, codegen second).

```
Sub-project A  (deterministic GIS runtime — NO LLM)
  RasterSpace + GeoTIFF loader + spatial ops + HANDCRAFTED raster-SIR
  + spatial-spread gate + minimal map
  ⇒ working, testable, gateable software on its own

Sub-project B  (autonomous layer, ON TOP OF A)
  GIS intent axis + GIS codegen templates
  ⇒ "one sentence → GIS raster model" that passes A's gate

Then WIDEN by layer:
  L1/L2/L3 +PointSpace, +VectorSpace · L4 full spatial-type intent ·
  method-transfer on GIS · GIS literature corpus · basemap viz
```

Each of A, B, and each widening item is its **own** spec → plan → build.

## 5. Sub-project A — deterministic GIS runtime (spec)

### A.1 RasterSpace (Risk 4 — it is NOT just Grid reuse)

`RasterSpace` = the existing discrete grid **plus georeferencing**:

- Backed by a `width × height` cell lattice (same neighbor logic as Grid: Moore /
  von Neumann, radius).
- Carries **geo metadata**: an **affine transform** (origin + pixel size + rotation),
  a **CRS**, and a **nodata** mask.
- **Coordinate contract (write this down, or everything downstream is subtly wrong):**
  - Agents live in **cell coordinates** `(col, row)` — like Grid.
  - The affine transform maps cell ↔ **world coordinates**, used for data I/O and
    map output **only**.
  - **CRS-agnostic / reprojection-first** (global cities demand it). The space
    carries the dataset's **real source CRS** and reprojects via `pyproj` as needed
    — **never hardcode one CRS**. Metric ops (distance/area) reproject to an
    appropriate **equal-area / projected** CRS; lat/lon degrees are never used for
    Euclidean math. The skeleton exercises one real CRS end-to-end (GHSL's), but
    the interface stays CRS-parametric.
- A field value per cell (population density, land use, …) via the existing
  `set_spot_property` hook — but RasterSpace owns the transform/CRS that hook lacks.

### A.2 GeoTIFF loader (Risk 5 — data fixtures)

- Read a GeoTIFF → `(2D array, affine transform, CRS, nodata)`.
- Lazy `import rasterio` inside the function.
- **Fixture = real open data, parametric & global.** A `fetch_clip` script takes a
  city/bbox and clips **GHSL GHS-POP** (EU Commission, open / free-reuse with
  attribution) to a small window (~100×100 cells, tens of KB) → committed as the
  default fixture, with a `data/README` recording **provenance + license/attribution**.
  Any global city is a bbox swap; **no city is hardcoded**. Never commit large or
  licensed data — only the small clip plus the regeneration script.

### A.3 Spatial ops

- Cell neighborhood: reuse Grid Moore/von Neumann.
- Metric distance: cell delta × pixel size (from the transform) → meters.

### A.4 Handcrafted raster-SIR model

- Agents seeded across cells weighted by the density field.
- SIR on the cell neighborhood; transmission scaled by local density.
- Deterministic with a fixed seed.

### A.5 Spatial-spread gate (Risk 3 — define it, don't hand-wave)

The gate asserts a **deterministic spatial signature**, not just "SIR peaks":

- **Spread:** the infected-cell **centroid spread radius** grows from the seed over
  time (monotone-ish increase early).
- **Density coupling:** final infected fraction is **higher in high-density cells**
  (positive sign of corr(density, infected)).
- **Clustering:** infection is spatially **clustered**, not random — e.g.
  **Moran's I of the infected field > a random-shuffle baseline**.

(Exact thresholds captured from the handcrafted run, like the existing science gate.)

### A.6 Minimal map output (Risk 7)

- `matplotlib` `imshow(density)` + scatter of infected agents; headless-safe.
- **No basemap deps** (cartopy/contextily) in the skeleton.

### A.7 Acceptance

- Handcrafted raster-SIR runs end-to-end on the fixture; spatial-spread gate PASS;
  map PNG produced; **base (non-GIS) `engine_oracle` still green** (proves zero-change).

## 6. Sub-project B — autonomous layer (spec)

### B.1 GIS intent axis (Risk 6)

Extend the Phase -1 detector with an **orthogonal spatial dimension** (the
reproduce/originate/cross_domain/idea intent is unchanged):

- `is_gis: bool` + `spatial_type: none | raster | point | vector`.
- **Explicit signals:** "GIS", "shapefile/GeoTIFF/raster", lat/lon, "map",
  a real place name **paired with** real geographic data.
- **Inferred suitability:** real geographic landscape, administrative regions,
  density/land-use fields, real-world locations driving the mechanism.
- **Confidence-gated**, same machinery as ⑤; **safe default = non-GIS**.
- **GIS detected but no data source → clarification halt** (ask for the GeoTIFF /
  data), do not crash.

### B.2 GIS codegen templates (Risk 2 — the hard, LLM-dependent part)

- A GIS branch in codegen that emits "load `<data>` via the GeoTIFF loader → build
  `RasterSpace` → run the mechanism on it".
- `MechanismSpec` gains a GIS-space descriptor.
- **Guardrails** (the LLM gets CRS / raster indexing / cell↔world mapping subtly
  wrong): deterministic checks on generated code (correct loader call, no
  degree/meter mixing, indexing within bounds) — same anti-fabrication discipline as
  the existing codegen-fidelity gates (see ADR-013 in this repo).

### B.3 Acceptance

- A one-sentence GIS story → generated raster model that **passes Sub-project A's
  spatial-spread gate** on the fixture.

## 7. Widening backlog (destination, post-skeleton)

- **PointSpace** (real-coordinate agents) + CSV/GeoJSON point loader + KD-tree neighbors.
- **VectorSpace** (polygons/lines as the agent space) + shapefile/GeoJSON loader +
  point-in-polygon + region adjacency. (Hardest geometry; deliberately last.)
- **Full spatial-type intent** detection + per-type codegen.
- **Method-transfer on GIS** — borrow mature spatial-analysis methods (spatial
  autocorrelation, hot-spot detection, Ricci curvature on the spatial interaction
  graph, …) and apply them to an ABM's intermediate **spatial** state.
  ⚠️ **Design rationale lives in the PRIVATE `unified-abm-platform-docs/strategic-adrs/`
  (ADR-012), which was purged from this repo's history (Risk 9).** Point there; do
  not re-derive it publicly.
- **Regional datum / CRS handling** — reprojection across the world's CRSs, with
  **pluggable region-specific datum corrections**. The hardest case is **China's
  GCJ-02 / BD-09**: a legally-mandated **nonlinear** offset from WGS-84 (~50–500 m)
  that **standard PROJ/`pyproj` does NOT handle** (needs a dedicated transform lib),
  plus **CGCS2000 / Gauss-Krüger / China-Albers** for metric work. Mixing a WGS-84
  raster with GCJ-02 civilian-map data silently offsets everything. Its own widening
  item, with a dedicated correctness gate. (China is one region among many — the
  point is the CRS layer is built so any region plugs in.)
- **GIS literature corpus** over fetched GIS+ABM papers.
- **Basemap visualization** (cartopy/contextily) as an additional viz option.

## 8. Strategic: reunification plan (Risk 8)

This repo is a hard fork of the published abm-auto. Because GIS is **additive /
zero-change**, the natural end-state is that the GIS path merges back into the main
repo as the `[gis]` extra.

- **Keep the GIS path import-isolated** (its own modules, lazy GIS imports) so a
  future merge is a clean *add* with no conflicts against the existing path.
- **Decision point:** at A+B completion, decide merge-back vs permanent-separate.
  Until then, GIS develops here without destabilizing the public release.
