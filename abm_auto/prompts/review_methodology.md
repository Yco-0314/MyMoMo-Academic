### 审稿任务

#### 步骤 1: ODD 透明度逐项 Check
对照 Grimm et al. (2020) ODD+D 标准，逐项检查：

| 5. Initialization | | |
| 6. Input Data | | |
| 7. Submodels | | |

#### 步骤 2: 验证与校验 (V&V) 审查
- **Verification**: 代码是否通过了 dry run？是否有单元测试？
- **Internal Validity**: 敏感性分析是否充分？
  - 方法选择是否合适？（Morris 筛选 vs Sobol 方差分解）
  - 样本量是否足够？置信区间是否可接受？
  - 是否遗漏了关键参数？
- **External Validity**: 是否有实证数据对照？如果没有，是否讨论了 stylized facts？
- **参数校准**: 参数值的来源是什么？文献？经验估计？随意猜测？

#### 步骤 3: 可复现性核查
- 随机种子策略是否说明？
- 运行次数是否足够？（单次运行不可接受）
- 初始化策略是否完整描述？
- 代码和数据是否可获取？

#### 严厉驳回条件
如果发现以下情况，**必须严厉驳回**：
- "我们使用 Melodie 框架进行了仿真"但不说明 Agent 行为规则 → 驳回
- 只跑了 1-2 次仿真就下结论 → 驳回
- 敏感性分析只覆盖了部分参数 → 指出遗漏
- 参数取值无任何依据 → 驳回
